## 1. 为什么 SFT 不够

SFT 在人工写的"指令→完美回答"上训练模型。问题：

- **覆盖**：人工写答案烧钱，最多几千条，覆盖不了真实用户的千变万化
- **一致性**：不同标注员对"好的回答"有不同理解
- **智能体**：SFT 只告诉模型"这个输入对应这个输出"，没告诉它"哪种回答更好"

RLHF 解决的事：**让模型能从 N 个候选回答中挑出最好的那个——即使这个问题在 SFT 数据中从未出现过**。

## 2. 三步流程全景

```
┌───────────────────────────────────────────────────┐
│ 第 1 步: SFT                                       │
│ 预训练模型 + 人工高质量回答 → 学会"指令→回答"格式    │
├───────────────────────────────────────────────────┤
│ 第 2 步: 训练奖励模型 (RM)                          │
│ SFT 模型生成多个回答 → 人工排序 → RM 学会打分       │
├───────────────────────────────────────────────────┤
│ 第 3 步: PPO 强化学习                               │
│ SFT 模型 = 策略 π, 生成回答 → RM 给奖励             │
│ → PPO 更新 π, 加上 KL 约束不让偏离 SFT 过远         │
└───────────────────────────────────────────────────┘
```

> 💡 **核心洞察**：第二步把昂贵的"写答案"变成了便宜的"排序"——标注员只需说 A 比 B 好，不用自己写。排 C(4,2)=6 对比较可以产生 6 个训练信号，而写 4 个答案只有 4 个。

## 3. 奖励模型：教模型"打分"

### 3.1 Bradley-Terry 偏好模型

对同一 prompt x，两个回答 y_w（好）和 y_l（差），人类偏好 y_w 的概率建模为：

```
P(y_w ≻ y_l | x) = exp(r(x, y_w)) / [exp(r(x, y_w)) + exp(r(x, y_l))]
                  = σ(r(x, y_w) - r(x, y_l))
```

其中 r 是奖励模型（通常是去掉最后分类头的 SFT 模型，把隐藏状态投影成标量）。

### 3.2 损失函数

```
L_RM = -E[log σ(r(x, y_w) - r(x, y_l))]
```

拉大好坏回答之间的奖励差距。如果 r(y_w) = 3.2 而 r(y_l) = 1.8，差 = 1.4 → σ(1.4) = 0.802 → loss = -log(0.802) = 0.22。如果差距小（0.1）→ σ(0.1) = 0.525 → loss = 0.64——模型被严惩。

### 3.3 手算一个 2 样本 batch

```
样本 1: r_w=2.5, r_l=1.0, diff=1.5 → σ(1.5)=0.818 → -log=0.201
样本 2: r_w=1.2, r_l=1.1, diff=0.1 → σ(0.1)=0.525 → -log=0.644

batch loss = (0.201+0.644)/2 = 0.422
```

## 4. PPO + KL 约束：别跑太远

PPO 的目标函数：

```
L_PPO = E[ r(x,y) - β · KL(π_θ || π_SFT) ]
```

两项拆解：

| 项 | 含义 | 作用 |
|----|------|------|
| r(x,y) | 奖励模型给当前回答的打分 | 鼓励好回答 |
| -β·KL | 当前策略与 SFT 的 KL 散度 | 别让模型变味 |
| β | 控制"奖励 vs 安全"的杠杆 | 通常 0.01~0.1 |

**为什么要 KL 约束？** 纯追求高奖励 → 模型会"作弊"找到奖励模型的盲区来刷高分（比如重复"太棒了！"这类无害废话），同时遗忘 SFT 学到的语言流畅性。KL 约束 = PPO 的"缰绳"。

PPO 的裁剪目标（防止更新过大）：

```
L_CLIP = min( ratio × A, clip(ratio, 1-ε, 1+ε) × A )
         其中 ratio = π_θ(y|x) / π_old(y|x)   (新旧概率比)
              A = 优势函数 ≈ r - baseline
              ε = 0.2 (典型值)
```

## 5. 手算一轮 PPO 更新

简化设定：一个 prompt，两个候选 token"好"和"坏"，当前策略概率 π_θ = [0.3, 0.7]，旧策略（SFT）概率 π_old = [0.5, 0.5]。

```
ratio = [0.3/0.5, 0.7/0.5] = [0.6, 1.4]
```

假设奖励模型对"好"给了 r=+1，对"坏"给了 r=-1，baseline=0，所以 A = r：

```
L_unclip = 0.6×1 + 1.4×(-1) = 0.6 - 1.4 = -0.8   (偏向"坏", 不好)
L_clip   = min(0.6, 0.8)×1 + min(1.4, 1.2)×(-1)   (ε=0.2 → clip范围 [0.8,1.2])
         = 0.6×1 + 1.2×(-1)
         = 0.6 - 1.2 = -0.6
```

取 min(L_unclip, L_clip) = -0.8 还是 -0.6？实际上 PPO 用的是负的策略梯度：

```
真正目标是对"好"增大概率:  clip 防止 ratio 太大导致一次更新太猛
对"坏"减小概率:          clip 防止 ratio 太大（因为 1.4 > 1.2, 取 1.2）
```

> ⚠️ 这是简化的直觉理解。完整的 PPO 还涉及值函数估计、GAE（广义优势估计）和熵奖励，但精神就是上述。

## 6. MATLAB：简化 RLHF 流程

```matlab
% ============================================================
% RLHF_SIMPLE.m
% 两步简化 RLHF: 训练奖励模型 + 带 KL 的 PPO 更新
% ============================================================
clear; clc;

fprintf('=== 简化 RLHF 演示 ===\n\n');

%% 第 2 步模拟: 训练奖励模型 (简化: 直接优化 Bradley-Terry)
fprintf('--- 奖励模型训练 ---\n');
% 3 个人类排序对
pairs = [
    2.5, 1.0;   % pair1: 好回答得分 2.5, 坏回答得分 1.0
    3.0, 2.0;   % pair2
    1.8, 1.7;   % pair3 (difficult case)
    ];

% 损失: -log(sigmoid(r_w - r_l))
diffs = pairs(:,1) - pairs(:,2);
loss_rm = -mean(log(sigmoid(diffs)));

fprintf('pair 差异: [%.1f, %.1f, %.1f]\n', diffs);
fprintf('RM 损失: %.4f\n', loss_rm);
fprintf('(pair3 差异小 → 贡献大损失 → 模型被 push 拉开差距)\n');

%% 第 3 步模拟: PPO 更新 (极简)
fprintf('\n--- PPO 更新 ---\n');
beta = 0.1;  % KL 惩罚系数
epsilon = 0.2;  % PPO clip

% 假设对 2 个 token 的策略
pi_old = [0.5, 0.5];    % SFT 策略（旧策略）
pi_new = [0.3, 0.7];    % 当前策略
rewards = [1.0, -1.0];  % 奖励模型打分

ratio = pi_new ./ pi_old;
fprintf('ratio = [%.2f, %.2f]\n', ratio);

% 未裁剪目标
L_unclip = ratio .* rewards;
% 裁剪目标
L_clip = min(max(ratio, 1-epsilon), 1+epsilon) .* rewards;
% PPO 取 min
L_ppo = min(L_unclip, L_clip);

fprintf('L_unclip = [%.2f, %.2f]\n', L_unclip);
fprintf('L_clip   = [%.2f, %.2f]\n', L_clip);
fprintf('L_ppo    = [%.2f, %.2f]\n', L_ppo);

% KL 惩罚
kl = sum(pi_new .* log(pi_new ./ pi_old));
fprintf('\nKL(π_new || π_old) = %.4f\n', kl);

final_obj = sum(L_ppo) - beta * kl;
fprintf('最终目标 = %.4f + PPO - %.4f×KL = %.4f\n', sum(L_ppo), beta, final_obj);

%% 辅助函数
function y = sigmoid(x)
    y = 1 ./ (1 + exp(-x));
end
```

## 7. RLHF 的副作用

| 副作用 | 原因 | 表现 |
|--------|------|------|
| 谄媚（Sycophancy） | RM 给"符合用户预期"高分 | 附和错误观点 |
| 过度拒答 | 安全 RLHF 让其对所有敏感请求拒答 | 拒绝无害请求 |
| 模式坍缩 | 奖励最大化 → 回答趋同 | "这是一个很好的问题"泛滥 |
| 奖励篡改（Reward Hacking） | 模型发现 RM 盲区 | 写长但不真实的回答 |

> 💡 后续演进：DPO（Direct Preference Optimization，2023）直接把偏好数据转化为损失，跳过显式的奖励模型——更简洁，在 Llama 3 等模型中得到应用。

## 📌 本章要点

1. RLHF 三步：SFT（学格式）→ RM（学打分）→ PPO（学偏好）
2. RM 用 Bradley-Terry 模型将"好坏差异"转为概率
3. PPO 剪裁目标防止更新过猛，KL 约束防止模型遗忘语言能力
4. 奖励最大化 vs 保持语言能力是一对永恒的张力
