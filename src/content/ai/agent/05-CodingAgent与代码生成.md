## 1. 七个核心工具：Coding Agent 的极简工具箱

一个基础 Coding Agent 只需七个工具，就能覆盖几乎所有核心动作：

| # | 工具 | 作用 |
|---|------|------|
| 1 | Code Interpreter | 隔离沙盒安全执行 Python |
| 2 | Bash Shell | 执行命令、跑测试 |
| 3 | 读文件 | 读取代码/配置/日志 |
| 4 | 写文件 | 创建或完全重写 |
| 5 | 编辑文件 | 局部修改（迭代核心） |
| 6 | Glob（搜文件名） | `**/*.py` 定位文件 |
| 7 | Grep（搜内容） | 搜特定文本模式 |

> 💡 七个工具虽简单，组合起来能完成非常多样化的任务。而且**代码生成不只是写程序——它是通用的问题解决手段**：数学推理可以写代码求解，业务规则可以代码固化，缺工具可以临时写一个。这就是为什么每个通用 Agent 都该有 coding 能力。

## 2. 从 Manus 到 OpenClaw：文件系统作为中枢

**核心洞察**：Coding Agent + 文件系统，是开放任务型通用 Agent 最核心的技术基础。为什么是 Coding 而非其他？**因为几乎所有高效的内容生成最终都要落到代码上**——PPT 本质是 OOXML 代码，数据分析是 Python 脚本，连 Computer Use 的操作序列都能固化成 RPA 代码。代码生成是效率最高、成本最低、可复用性最强的能力基座。

**OpenClaw 架构**：
```
文件系统（中枢）
├── MEMORY.md          长期记忆（高层事实、用户偏好）
├── SOUL.md            Agent 身份与行为规则
├── daily/YYYY-MM-DD.md  按日归档日志
└── 知识库文件          任务经验（自我进化）
```

**选 Markdown 而非向量数据库**的原因（看似反直觉，实则有效）：
- 用户可直接打开修改记忆（记错了删那一行即可）
- 天然保留时间顺序，避免语义检索的时间混淆
- 可 Git 版本控制和回滚
- **Agent 能写文件 = 能自我进化**（第 8 章"外部化学习"）

## 3. Coding Agent 的安全：致命三要素与四类边界

### 3.1 Simon Willison 的"致命三要素"

三者齐备即构成完整攻击闭环，系统即属高危：

1. **访问私有数据** —— 能读用户文件和密码管理器
2. **暴露于不受信任内容** —— 处理的邮件/网页可能含恶意载荷
3. **具备外部通信能力** —— 能发邮件、执行命令

> 攻击路径闭合：恶意指令藏在不受信任内容中 → 驱使 Agent 读私有数据 → 经对外通道传出。

**李博杰补充第四维——持久记忆**：不是并列条件，而是攻击放大器。攻击者可把恶意指令写入长期记忆，跨会话潜伏，把一次性攻击升级为长期潜伏。

### 3.2 四类边界（对应防线）

| 边界 | 防线 |
|------|------|
| 数据边界 | 凭证文件（~/.ssh、token）根本不挂载进沙盒 |
| 输入信任边界 | 外部内容来源标注、结构化角色隔离 |
| 输出影响边界 | **默认断网**，白名单代理放行——掐断外传通道 |
| 跨会话边界 | 写入长期记忆的内容需同等信任审查 |

### 3.3 三个关键工程决策

**① 语义解析而非关键字黑名单**：`rm` 被禁，攻击者用 `$(echo rm) -rf /` 绕过。语义解析理解命令参数的真实效果，识别 `find -exec rm` 这类嵌套危险操作。

**② 推测性执行（让安全检查隐形）**：把"展示"和"放行"拆开并行——界面先显示进度提示（无副作用），后台同时跑安全检查。**安全性不以牺牲用户体验为代价**，是 Harness 设计的最高境界。

**③ 默认断网 + 结构化错误返回**：超时/超限返回结构化错误（"执行超 120 秒被终止"）而非静默杀死，让 Agent 下一轮能修正策略。

## 4. 代码作为元能力：六个作用方向

**元能力** = 能创造其他能力的能力。代码精确、可执行、可组合，因此是元能力。六个方向按"作用对象由内向外"组织：

```
1. 思维本身     → 代码替代易错的自然语言推理（思考工具）
2. 业务规则     → 把模糊政策编码为可执行约束（规则约束）
3. 内容呈现     → 生成 PPT/视频/可视化（多媒体生成）
4. 系统接口     → 桥接异构 API（系统适配器）
5. 用户界面     → 动态构造表单（生成式 UI）
6. Agent 自身   → 用代码创造新 Agent（自举）
```

## 5. 代码作为思考工具：概率 vs 精确

**核心矛盾**：模型思考本质是**概率性、近似**的，数学逻辑要求**确定性、精确**的答案。

**经典例子**（集合问题）：

```
纯自然语言推理（易错）:
"60% 选数学=24人，45% 选物理=18人，25% 都选=10人，
 只选物理 = 24 - 10 = 14 人"  → 误从数学人数减，答案错

代码推理（精确）:
only_phys = int(40*0.45) - int(40*0.25) = 18 - 10 = 8 ✓
```

**Wolfram 的洞察**：LLM 前已有符号计算系统（Wolfram Alpha），能做精确计算但自然语言理解脆弱；LLM 恰好相反。**新协同模式**：LLM 负责理解自然语言、转化为形式化语言（SymPy/Python），符号引擎负责精确计算。

> 💡 更深层规律（实验 5-2 揭示）：**模型与脚手架此消彼长**。模型强→脚手架可以薄（自己就能想对）；模型弱→脚手架要厚（把关键推理交给代码求解器兜底）。脚手架做多厚，取决于你手上模型的能力边界。

## 6. 代码作为业务规则的约束：三重保障

以 τ-bench 航班取消政策为例，展示了**三重保障**：

```
① 系统提示词的自然语言规则      → 帮助理解和解释政策
② 工具描述 + expected_* 参数     → checklist，引导模型调用前逐条核对
③ 服务端基于数据库真值的校验     → 最后守门员
```

**关键设计**（这是全书最精彩的工程细节之一）：

```python
# 所有政策事实一律从数据库读取，绝不采信模型自报的值
r = db.get_reservation(reservation_id)
now = server_clock.now()   # 服务端时钟，而非模型提供

# 模型自报值与真值不一致时记录告警
if expected_cabin_class != r.cabin_class:
    log_mismatch(...)
```

- **第一层 checklist 价值**：`expected_*` 参数迫使模型显式写出判断依据，填写参数过程 = 强制核对，常常在准备调用时自己就发现"经济舱未购保险"而放弃
- **第二层守门员价值**：舱位、保险、时间**全部来自服务端数据库**，绝不采信模型自报。否则模型报错一个值，守门员就形同虚设

> 💡 **最后一道防线必须建立在模型无法伪造的数据之上**。独立性不仅指独立模型，更指**独立数据来源**。

## 7. 忠诚度与信任边界下移

### 7.1 委托方忠诚（principal loyalty）

模型训练默认"谁说话帮谁"，但真实 Agent 常处多方委托——替你砍价的 Agent，对面是利益相反的对手，此时"谁说话帮谁"是危险的默认。

**忠诚度守则**：
- 保护主人私密信息乃至它的"存在性"
- 拒绝时不逐条念出拒绝清单（那本身就在泄露）
- 私下的底线 ≠ 对外的立场
- 只执行主人明确、具体的指令
- 顶住重复施压

> 提示注入本质上就是一次"策反"（第二、四章）。Harness 要显式钉死"忠诚对象"。

### 7.2 信任边界下移：权限内嵌的数据对象

对高危数据操作，"更可能守规矩"还不够——要把约束从"寄望 Agent 自觉"下移到数据层强制执行。

- LLM 生成的 handler 经常漏掉权限检查，自主 Agent 又直接对生产数据下手 → 应用层前提被打破
- **权限内嵌数据对象（Permission-Embedded Data Objects）**：每个数据实体在人类审查过的 schema 里自带声明式权限规则，运行时流水线每次写入强制
- 自主 Agent 以受限身份运行——即便被策反也越不过雷池

> 核心原则：**当写代码的和跑代码的都可能不可信时，真正可靠的约束不能待在被生成的代码里，而要待在它下面那层人类审查过的地基里。**
