## 1. 为什么 Agent 不会自动学习

一个根本问题：**如果上下文窗口无限长，把 Agent 经历的一切都塞进去，它是不是就能自动学会一切？**

**答案是否定的**——原因藏在第二章的注意力机制里：

> 注意力擅长"查找"（第 37 个笼子是什么猫），却不擅长"归纳统计"（100 个笼子共多少黑猫）。把原始经验堆进上下文，模型能"记得"，却不会自动"提炼"成可复用规律。

**两个致命问题**：
1. 无限上下文 ≠ 自动学习——从"具体记录"到"一般模式"的那步压缩，没人替模型完成
2. 上下文越长噪声越多（第二章的"上下文腐化"），检索质量反而下降

> 💡 **Karpathy 的洞察反过来读**：模型"记性差"是特性而非缺陷——它逼我们主动、显式地做知识提炼。**学习不会自动发生，必须被显式设计出来。**

## 2. 三种学习范式与外部化学习的定位

| 范式 | 机制 | 优点 | 缺点 |
|------|------|------|------|
| 后训练（改权重） | RL 把经验固化为"肌肉记忆" | 成功率高、延迟低 | 更新成本高、周期长 |
| 上下文学习（ICL） | 提示词给示范，临时适应 | 成本低、见效快 | 会话结束就消失 |
| **外部化学习** | 知识沉淀到文件/知识库/工具 | **持久、可解释、可修正** | 需要额外算力提炼 |

> 💡 **外部化学习是开发者最容易忽略的一条路径**。三者协同而非竞争：事实知识 → RAG/外部化存储；稳定行为 → 后训练固化；临时信息 → 上下文学习。

**本章聚焦"不改权重"的外部化学习**——把经验外部化为知识/Skill，把能力外部化为工具。

## 3. 外部化学习循环

```
完成任务产生原始经验 → 提炼(总结·压缩·结构化) → 存入外部系统 → 检索复用 → (循环)
```

**核心哲学**：与其期待模型记住一切，不如在任务完成后**用额外算力**把经验总结、压缩、结构化，存入可持久化、可检索的外部系统。

**反面场景**（为什么需要它）：客服 Agent 第一次处理退款花了 15 分钟探索（打 3 次电话、试 2 种话术）。没外部化学习，下次遇到同样请求**从头再花 15 分钟**。关键是"**自主**"二字——不是人类为 Agent 写文档，是 Agent 自己总结经验。

## 4. 从经验中学习：策略摘要与工作流录制

两种互补的经验积累方式：

| 机制 | 类比 | 做法 | 适用 |
|------|------|------|------|
| **策略摘要** | 解题思路笔记 | 把成功轨迹提炼为结构化经验摘要（方法、坑、关键步骤） | 可迁移的高层策略 |
| **工作流录制** | 操作录像 | 把操作序列固化为可回放的自动化工具 | 流程固定的重复任务 |

**策略摘要的判断标准：可迁移性**——当前学到的教训，能否在未来类似任务复用？只对某次特定输入有效的修正，不应进入长期记忆。

**四个层面**（表 8-2）：
```
知识提炼：策略摘要、工作流录制、失败反思
知识组织：Skills、睡眠整合
知识应用：系统提示词优化
工程支撑：跨会话续跑
```

### 从失败中学习

失败反思同样重要——不仅记成功，也记"踩了什么坑"。睡眠学习（8.4.3）是用户记忆的自主进化——离线整理，越用越准（衔接第 3 章）。

## 5. 从工具使用者到工具创造者

### 5.1 预定义工具集的根本性局限

- 现实世界的工具数量**几乎无限**，无法预先枚举
- 接口常不匹配、大量服务不是 Agent 友好格式
- **预定义范式把 Agent 能力边界锁死在人类工程师的预见上**

### 5.2 范式转变：最小预定义，最大自我进化

Alita 论文的核心思想：

> **最小预定义，最大自我进化**——少量精心设计的基础工具提供基本能力，自我进化机制赋予无限扩展潜力。

**把全球开源生态变成 Agent 的资源池**：遇到新任务 → 搜索最贴近的库 → 写胶水代码拼接 → 积累复用。

### 5.3 自我进化流水线

```
① 需求识别(现有工具不足) → ② 工具搜索(开放世界查找) → ③ 代码封装 → ④ 工具注册(纳入库可复用)
```

**两种能力**：
1. **集成现有工具**（Alita 例子）：MCP 头脑风暴 → Web Agent 搜索 → Manager Agent 理解 API → 封装为 MCP 工具
2. **从头编写新工具**：把"流程"代码化为可精确执行、可持久化的工具

**关键差异**：传统 Agent 的代码执行是**一次性**的（跑完就丢）；自我进化范式下，代码是**可复用模块化工具**，持久化保存。

## 6. Voyager：开放世界里的持续学习

Minecraft Agent 的自我进化范式，三个关键要素：

```
课程生成器 → 迭代提示机制 → 技能库
(提出渐进任务)  (生成调试代码)  (存储可复用技能)
```

- **自动课程生成器**：根据当前状态、已掌握技能，提出"最近发展区"的下一个目标（既不太难也不简单）
- **技能库**：成功动作序列提炼为可执行代码，层次化可组合（"制作木镐"调用"砍树"+"制作木板"）
- **迭代提示机制**：失败时收集反馈，引导生成改进代码

> 结果：发现的独特物品数量是基线的 **3.3 倍**。证明了"从临时适应到永久积累"的可行性。

## 7. 三层能力积累与安全边界

### 7.1 三层能力

| 层 | 内容 | 沉淀方式 |
|----|------|----------|
| 工具层 | 新工具基于已有工具构建（先"股价"后"组合分析"） | 工具库 |
| 知识层 | 哪些库适用哪类任务、哪些 API 无需 key | 知识库 |
| 策略层 | 改进自我进化策略本身（元学习） | 短期 Skill，长期 RL 固化 |

> 💡 策略层展示了**外部化学习与后训练的接力分工**：先用可解释、可修改的外部载体快速迭代，稳定后再固化到参数。

### 7.2 安全边界

| 风险 | 说明 | 缓解 |
|------|------|------|
| **供应链攻击** | 自主下载的恶意 PyPI/npm 包被执行 | 沙盒运行 + 自动安全扫描 |
| **能力漂移** | 持续学习逐渐偏离设计者意图 | 工具类型白名单 + 限制增长 + 定期人工审核 |

## 📌 本章要点

1. **无限上下文 ≠ 自动学习**——学习必须显式设计（检索而非推理）
2. 三种学习范式：后训练（固化）、上下文（临时）、**外部化（持久可修正）**——后者最易忽略
3. 外部化学习循环：完成任务 → 提炼 → 存入 → 检索复用
4. 策略摘要（解题思路）vs 工作流录制（操作录像），判断标准是可迁移性
5. **从工具使用者到工具创造者**：最小预定义、最大自我进化，开源生态是资源池
6. Voyager 三层：课程生成器 → 迭代提示 → 技能库，3.3 倍物品发现
7. 三层积累（工具/知识/策略）+ 安全边界（供应链攻击、能力漂移）
