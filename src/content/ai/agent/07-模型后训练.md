## 1. 三阶段全景：一张表看懂

| 阶段 | 数据 | 优化目标 | 学到什么 | 代价 |
|------|------|----------|----------|------|
| 预训练 | 海量原始文本 | 预测下一个词 | 语言规律、世界知识、推理 | 极高（千万美元级） |
| SFT | 几千~几万条示范对 | 预测下一个词（只算回答损失） | 指令遵循、格式、协议 | 低（几小时~几天） |
| RL | 任务 + 奖励函数 | 最大化期望奖励 | 可迁移决策策略、新解法 | 高（SFT 的几十~上百倍） |

> 💡 核心洞见：模型输出本质是**概率分布**。三个阶段区别只在于"想要什么"、"用什么信号定义想要"。

## 2. SFT 的本质：换了数据的"预测下一个词"

**本章第一个关键认知**：SFT 在数学上和预训练是**同一个任务**——都是预测下一个词。差别只有两点：

1. **数据不同**：预训练用原始文本，SFT 用"输入→输出"示范对
2. **损失只算在回答上**（loss masking）：屏蔽问题部分，只对回答回传梯度

所以"**SFT 记忆**"顺理成章：优化目标是让标注答案每个 token 概率最高，就是"把标准答案背下来"。能力边界钉死在示范数据上。

> 💡 **SFT 固化的不是"知道什么"（事实知识），而是"该怎么说、怎么做"（协议性知识）**。事实性知识要靠预训练或 RAG。

**LoRA（工程默认项）**：挂一个小"补丁"（低秩矩阵），参数量仅 1-5%。几个实践规则：应用到所有主要权重矩阵（尤其 MLP 层）；学习率约是全参的 10 倍；SFT 用中高 rank（64-256），RL 用小 rank（8-32）。

## 3. 为什么先 SFT 后 RL：先形后神

RL 不看标准答案，让模型自己生成再打分。但**要打分，首先得能解析输出**——模型吐出一团混乱文本，奖励函数无从算起。

所以 SFT 扮演"先把话说利索"：用少量示范让输出格式稳定、可解析，RL 才有打分的起点。

> 🎨 借用中国画的说法：**SFT 先把"形"（格式）立起来，RL 再追求"神"（策略、泛化）**。

**边界条件**："必须先 SFT"只在"较小模型 + 严格结构化输出"下成立。**DeepSeek-R1-Zero 证明了强基模可以直接 RL**（涌现反思和长链思考），但代价是输出可读性差、中英文混杂，所以最终 R1 仍加回"冷启动 SFT"。**R1 从 Zero 到冷启动的往返，正是"先形后神"的最好注脚。**

## 4. SFT vs RL 的本质区别：记忆 vs 泛化

本章最重要的一张表（表 7-2）：

| 维度 | SFT | RL |
|------|-----|-----|
| 优化目标 | 最大化标注答案概率（极大似然） | 最大化期望奖励 |
| 学到什么 | 固定"输入→输出"映射（**记忆**） | 可迁移决策策略（**泛化**） |
| 分布漂移下 | 套用旧答案、性能下降 | 用同一策略重算、更稳 |
| 样本效率 | 高（几千条见效） | 低（几十~上百倍） |
| 训练稳定性 | 高 | 低、易震荡 |

### 4.1 三个深层机制

**① mass-covering vs mode-seeking（寻峰）**
- SFT 的极大似然是**覆盖式**的（雨露均沾，连质量一般的模式也分概率）
- RL（带 KL 约束，反向 KL 散度）是**寻峰式**的（赢者通吃，概率集中到少数高奖励的峰）
- 所以 RL 后的模型回答更"笃定"，但也容易牺牲多样性

**② offline vs online（为什么 RL 上限更高）**
- SFT 是离线：只能从固定示范学，天花板 = 示范者水平（60 分老师训不出 90 分学生）
- RL 是在线：模型自己下场试错，天花板 = 任务本身

**③ 验证—生成不对称**
- SFT 需要有人先写好答案；RL 只需要能判断答案好不好
- "认出好"比"做出好"容易得多 → RL 能训出超越任何现成示范的模型
- 这是 RLVR（可验证奖励）威力的来源

### 4.2 经典证据

卡牌游戏：SFT 训练时 J/Q/K=10，测试时 J 变 11，SFT 照用 10（记忆）；RL 用同一套策略重算（泛化）。

## 5. 奖励信号的设计空间：密度 × 表示形式

### 5.1 密度谱（多久给一次反馈）

```
稀疏 ────────────────→ 密集
二元奖励   里程碑奖励   过程奖励   密集连续
(成功=1)  (多维验证)  (每步反馈)  (每步部分分)
```

- **二元奖励**：有标准答案的任务够用（数学题、SQL）
- **稀疏奖励的困境**（Pine AI 打电话）：100 次尝试才偶然成功，因为 RL 只看到"失败"，看不到"客服说了需要信用卡后四位"这个环境反馈

### 5.2 表示形式谱（反馈长什么样）

| 范式 | 例子 | 特点 |
|------|------|------|
| 标量 | 7.2 分 | 无诊断能力 |
| 半标量 | 先分析再给 6.5 分 | 有依据但粗粒度 |
| **向量** | 信息准确 9/10、收集完整 6/10... | 精确定位短板（像体检报告） |
| **生成式** | 自然语言多角度分析 | 从一次失败学到改进方向，无需数百次试错 |

> 💡 生成式奖励模型（DeepSeek）：让模型自己总结"优秀应该怎样"、逐条评价、系统自动检查准确性。判别式 RM（Bradley-Terry）只输出标量，生成式 RM 把"为什么好/差"也讲出来。

## 6. 过程奖励 vs 结果奖励

| | 过程奖励（PRM） | 结果奖励（ORM） |
|---|---|---|
| 反馈时机 | 每步 | 终点 |
| 优点 | 降低信用分配难度、加速收敛 | 最大探索自由度 |
| 缺点 | 人工设计偏见、限制探索 | 训练难、样本需求高 |
| 比喻 | 逐题批改 | 只看期末成绩 |

**信用分配的工程实现**：
- 折扣因子 γ 在多轮 LLM RL 中通常**直接设为 1**（任务就几轮，没必要打折）
- PPO 用 GAE（价值网络估"每步比预期好多少"）
- GRPO 把整条 response 当单一动作，优势均摊到所有 token——**单轮短任务没问题，长程多轮会稀释信号**
- turn-level 分摊是折中

> ⚠️ 关键取舍：当中间步骤正确性容易定义 → 过程奖励高效；当最优路径未知 → 结果奖励更有潜力（能发现"推切"这种人类没想到的新动作）。

## 7. RLVP：奖励结果，惩罚路径

**这是全书最前沿、最有原创性的部分**（作者自己的论文，arXiv:2607.07435）。一句话概括：**reward the outcome, penalize the path（奖励结果，惩罚路径）**。

### 7.1 要解决的问题

有一类约束（outcome-neutral constraints）结果奖励**不但学不会，还会反向激励违反**：

- 不要反复拨打已拒接的用户、不要在非工作时间行动、不要跳过身份验证、不要 `rm -rf`、不要改测试文件、不要覆盖没读过的文件

麻烦在于：**违反这些约束往往让"表面成功率"更高**（抄近路更快）。纯结果奖励反而主动激励违规——论文里几乎每一局都踩线。

### 7.2 核心洞察：真实环境是"不对称的验证器"

- **检测坏动作**（跑了破坏性命令）→ 便宜可靠（有明确特征）
- **判定进展**（是否朝目标推进）→ 昂贵易错（几乎和"解决任务"一样难）

所以环境能可靠提供的密集信号，本质是"路径上的惩罚"，不是"进展上的奖励"。

### 7.3 做法

在结果奖励之外，加一路可验证的路径信号：

```
R = O + β · Φ
```

- O：结果奖励（稀疏，真正的目标）
- Φ：路径信号，由**确定性规则引擎**逐动作给出（纯函数判断，不是学出来的裁判）

Φ 两种用法：
- **惩罚（−λ）**：每出现一次可机器判定的违规动作就扣分
- **守规/进展奖励（+μ）**：每出现一次可验证的好动作（满足前置条件、子目标达成）就加分

### 7.4 为什么有效：组内方差

GRPO 的优势本质是**组内方差**——如果一组 rollout 奖励完全相同，方差为零，贡献不出任何梯度。

**纯结果奖励的"零方差死局"**：
- **全败组**（训练早期）：任务太难，O 全是 0 → 方差零 → 白跑
- **全胜组**（训练后期）：任务快学会，O 全是 1 → 方差零 → 白跑

**惩罚永远能补回方差**（坏动作总是便宜可查）；**进展奖励只在"进展可达"时能补回**（定理证明里"待证目标数下降"可达 → 有用；软件修复里"通过测试比例"常不可达 → 没用）。

### 7.5 四条设计原则

1. **只惩罚可验证的"动作"，绝不惩罚"没进展"**（否则 Agent 学会"什么都不做"）
2. **结果奖励始终是主驱动力**（纯惩罚 → 不作为陷阱，成功率塌到零）
3. **每个惩罚配一个守规奖励**（给 Agent 指出路，而非只堵不疏）
4. **合规路径可达、惩罚靶子无法钻空子**（用确定性检查，而非学出来的评委）

### 7.6 实验效果

- TerminalBench：每局违规 3.71 → 0.66（约 6 倍），成功率基本持平——**"守规"几乎是免费的**
- miniF2F（进展可达）：达 0.9 成功率迭代数 7.0 → 4.4
- 链式文件操作："全败组"（浪费样本）比例 65% → 8%
- 反例（进展不可达的软件修复）：密集进展奖励无收益，印证"可达性才是门槛"

> 💡 RLVP 与 RLVR 的互补：RLVR 验证**结果**，RLVP 额外验证**过程**。两者叠加 = 既盯着"把事办成"、又盯着"办得规不规矩"——这正是能安全上线的 Agent 需要的。

## 📌 本章要点

1. 三阶段本质都是"调概率分布"，区别在"想要什么 + 用什么信号"
2. **SFT 本质 = 换了数据的预测下一个词**（loss masking），固化的协议而非事实

6. 过程奖励 vs 结果奖励：中间步骤可定义→过程，最优路径未知→结果
7. **RLVP**：奖励结果、惩罚路径，靠"坏动作便宜可查"补回组内方差，守规几乎是免费的
