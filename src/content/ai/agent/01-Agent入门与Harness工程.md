## 1. Agent = LLM + 上下文 + 工具：三大支柱

全书核心公式，用人体比喻：

| 支柱 | 对应 | 作用 | 强化学习映射 |
|------|------|------|--------------|
| LLM | 大脑 | 思考、决策 | Policy（策略） |
| 上下文 | 眼睛 | 决定 Agent 能"看到"什么 | Observation Space |
| 工具 | 手脚 | 决定 Agent 能"做"什么 | Action Space |

> 💡 三个词各自远比字面意思丰富。书里特别强调：上下文**不只是对话历史**，还包括工具定义——Agent "看到"的信息里包含了"有哪些手脚可用"。这个细节很多人忽略，却是 Agent 能力的关键。

## 2. ReAct 循环：Agent 的心跳

ReAct = **Re**asoning + **A**cting。你在 [deep-dives/10](../ai_theory/deep-dives/10-Agent%20ReAct循环.md) 已经手算过这个循环：

```
Thought（思考）→ Action（行动）→ Observation（观察）→ 循环直到完成
```

**本章的关键补充**：书里点出了 ReAct 的**脆弱点**——模型可能幻觉（编造不存在的工具）、选错工具、遇到错误无法自恢复。一个能跑的 Demo 和一个可靠的产品之间，隔着 Harness 工程这条鸿沟。

---

## 3. Harness 工程：从 Demo 到产品的鸿沟

### 3.1 核心定义

```
最小公式（Demo 视角）:  Agent = LLM + 上下文 + 工具
生产公式（生产视角）:    Agent = Model + Harness
                        = LLM + [上下文 + 工具 + 约束 + 验证 + 纠正]
```

**Harness = 围绕 LLM 这个核心组件构建的所有支撑代码**。用"Model"而不是"LLM"，是因为这些原则适用于任何有推理+工具调用能力的模型。

### 3.2 一个直击本质的例子

书里的退款场景：

| 环节 | 没有 Harness | 有 Harness |
|------|--------------|------------|
| 上下文 | 模型看不到退款政策 | 系统提示词写明 7 天退款政策 |
| 工具 | 不知道调哪个 API，编造结果 | 调用 query_order / process_refund |
| 约束 | 无 | 校验退款金额 ≤ 订单金额 |
| 验证 | 用户发现退款没发生 | 校验数据库状态确认成功 |
| 纠正 | 无 | API 超时自动重试 |

> 💡 **同一个模型，有无 Harness，结果天壤之别。** 这是全书最重要的一句话。

### 3.3 马具隐喻

没有 Harness 的模型像脱缰的野马——能力惊人，但无法可靠完成任务。Harness 就是"马具"（英文 harness 本义）。

## 4. 五个功能：约束、验证、纠正

Harness 五要素：

| 功能 | 职责 | 与上下文/工具关系 |
|------|------|-------------------|
| Context 上下文 | 提供感知信息 | 核心能力 |
| Tools 工具 | 提供行动手段 | 核心能力 |
| **Constrain 约束** | 设定边界：能做什么、不能做什么 | 围绕上下文/工具的安全边界 |
| **Verify 验证** | 自动判断操作结果对错 | 围绕工具执行结果的检查 |
| **Correct 纠正** | 发现问题自动修正/回退 | 围绕工具调用失败的恢复 |

**关键洞察（书里反复强调）**：

> 上下文与工具让 Agent "**能做事**"；约束、验证与纠正让 Agent "**不做错事**"。行业正在从"能做事"向"可靠地做事"转变。

书中举例 Claude Code 的 Harness 绝大部分代码是约束/验证/纠正，而非工具本身——工具（文件读写、命令执行、搜索）只是一小部分：

- 流程状态管理
- 多层上下文压缩
- 权限分类
- **熔断器（Circuit Breaker）**：连续错误时自动"断电"，像保险丝跳闸
- 错误恢复：捕获异常 → 回滚 → 重试 → 交还人类

## 5. 工程范式的演进：五波浪潮

```
软件工程 → 提示工程 → 上下文工程 → Harness 工程 → Loop 工程
（基础）   （第一波）   （第二波）     （第三波）      （最新）
```

- **提示工程**：优化输入给模型的指令
- **上下文工程**：系统性管理模型能看到的所有信息
- **Harness 工程**：扩展到"模型在什么系统中运行"——约束、验证、反馈循环、错误恢复
- **Loop 工程**：跨轮次的持续自主运转——谁发现下一件事、何时验证、何时算完成

**层层包含**：提示 ⊂ 上下文 ⊂ Harness ⊂ Loop。每一层都扩展了工程师的关注范围。

> 📊 书中用 LangChain 的案例佐证：Coding Agent 从 52.8% → 66.5%（Terminal Bench 2.0 从 30 名外到前 5），**改的不是模型，是 Harness**（自动检查执行结果、检测重复循环、优化思考策略）。

## 6. 三个核心原则：简单、透明、ACI

来自 Anthropic 的经验：

1. **保持简单** —— 从最简单方案开始，只在必要时增加复杂度。直接 API 调用优于复杂框架。每多一层抽象都是调试的新盲区。

2. **保持透明** —— 明确显示规划步骤、执行日志、决策轨迹。黑箱里的错误一旦发生，外部无法定位也无法纠正。

3. **设计好工具接口（ACI，Agent-Computer Interface）** —— 从 **Agent 的视角**设计接口，而非程序员视角。命名直观、参数有例子、容易误用的地方主动"防呆"（Poka-yoke，丰田生产体系术语——像 USB 只能单向插入，让错误从设计上无法发生）。

> 💡 ACI 是全书最精妙的概念之一：**模型与工具之间唯一的沟通通道就是接口本身**，模糊的接口会被模型放大成系统性错误。

## 7. 编排模式：工作流 vs 自主 Agent

| | 工作流（Workflow） | 自主 Agent |
|---|---|---|
| 执行路径 | 代码预定义，确定 | 模型根据环境反馈实时决定 |
| 优点 | 流程可控、安全、防跳过 | 灵活、适应开放式问题 |
| 缺点 | 缺变通性 | 成本高、复合错误风险 |
| 适用 | 可分解的固定子任务 | 无法预测步骤数的任务 |

**选型原则（"从简单到复杂"）**：

```
单个 LLM 调用 → 不行 → 工作流（固定子任务）→ 不行 → 自主 Agent（动态决策）
```

> ⚠️ Agent 系统是用**延迟和成本换任务性能**，应谨慎权衡。

## 8. 模型选型与护栏

### 8.1 模型选型要点

- **御三家**：OpenAI（GPT/o 系列）、Anthropic（Claude 系列）、Google（Gemini 系列）
- **国内**：豆包（低延迟）、Kimi（Agent 能力强）、Qwen/DeepSeek（开源可定制）
- **关键**：绝大多数 Agent 需要**支持思考（Reasoning）的模型**——多步思考、工具选择都需要推理能力
- **别只看排行榜**：在你自己的任务上做评估（第 6 章）

### 8.2 护栏：分层防御

按防护位置分三层：

| 位置 | 机制 | 例子 |
|------|------|------|
| 输入侧 | 相关性分类器、安全分类器、内容审核、规则保护 | 检测越狱 vs 提示注入 |
| 执行侧 | 工具风险评级 | 高风险操作需人工确认 |
| 输出侧 | PII 过滤器、输出验证 | 过滤身份证号 |

> 💡 **越狱 vs 提示注入的区别**：越狱是**用户自己**试图绕过模型安全限制；提示注入是**攻击者通过外部数据**（网页、文档）间接操纵模型。这个区分很重要。

**人工干预（Human in the loop）**两种触发：超过失败阈值、高风险操作。

## 9. 与你正在用的 Claude Code 的对照

这一章读完，你应该能看懂**你现在用的 Claude Code 到底在干什么**：

| 书中的概念 | Claude Code 里的体现 |
|------------|---------------------|
| 上下文工程 | 系统提示词 + 记忆 + 文件读取 |
| 工具 + ACI | 精心设计的工具 schema（Read/Edit/Bash 等） |
| 约束 | 权限模式、需用户授权的操作 |
| 验证 | 运行测试、检查输出 |
| 纠正 | 报错后自动重试/调整方案 |
| 熔断器 | 连续失败时停止、交还给你 |
| 护栏 | 高危操作（删除、覆盖）先确认 |

**你现在每次看我工作，观察到的"读文件→改代码→跑测试→报错→修正"的循环，就是这套 Harness 在运转。**

## 📌 本章要点

1. Agent = LLM + 上下文 + 工具（Demo），生产还要加**约束+验证+纠正**（Harness）
2. Harness 五要素：上下文、工具是"能做事"，约束/验证/纠正是"不做错事"
3. 工程范式五波：提示 → 上下文 → Harness → Loop，层层包含
4. 三个原则：简单、透明、ACI（从 Agent 视角设计工具接口）
5. 编排：从简单到复杂（单调用 → 工作流 → 自主 Agent）
6. 护栏分输入侧/执行侧/输出侧，越狱≠提示注入
