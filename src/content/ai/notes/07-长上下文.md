# 第七课：长上下文——为什么卡在 1M（2023–2026）

> 核心问题（你最初的问题之二）：**为什么上下文窗口从 4K 一路涨到 1M，却很难再突破？背后到底是什么技术限制？**

## 0. 先给结论

1M 不是一道"墙"，而是**四重限制叠加的缓坡**：

1. **注意力计算量 O(n²)**——越长越算不动
2. **KV Cache 显存 O(n)**——越长越存不下
3. **位置编码的外推失效**——没见过这么长的，模型直接懵
4. **注意力稀释**——能塞进去 ≠ 能用得好

下面逐个拆解，按"问题 → 解法"讲。

## 1. 限制一：O(n²) 的计算诅咒

第四课说过，自注意力要算一张 n×n 的相关性打分表：

| 上下文长度 | 打分表格子数 |
|---|---|
| 4K | 1600 万 |
| 128K | 164 亿（×1024） |
| 1M | **1 万亿**（×65536） |

而且每一层、每个头都要算一遍。

### 解法：FlashAttention（2022，Tri Dao）

- 革命性认知：注意力的瓶颈不是**算**（GPU 算力富余），而是**搬数据**——n×n 的中间结果在 HBM（显存）和 SRAM（片上缓存）之间来回搬运，慢在 IO 上
- FlashAttention 把计算**分块（tiling）**，在 SRAM 里边算边扔，永不落盘完整的 n×n 矩阵
- **数学上精确等价**（不是近似！），速度提升 2-4 倍，显存从 O(n²) 降到 O(n)
- 它让 O(n²) 从"完全不可行"变成"咬牙可行"，是长上下文的第一块基石

### 解法：稀疏/线性注意力

- 让每词只看局部窗口 + 少数关键位置，近似 O(n)
- 代表：Mistral 滑动窗口、DeepSeek NSA（2025）、Kimi MoBA（2025）
- 另一条路线：Mamba 等状态空间模型（2023），理论 O(n)，但纯 Mamba 在精确回忆上仍有短板，工业界多用混合架构

## 2. 限制二：KV Cache 显存爆炸

推理时，为避免重复计算，每个 token 的 K 和 V 向量会被**缓存**起来。代价：

```
KV Cache 大小 = 2(K和V) × 层数 × 隐藏维度 × 序列长度 × 字节数
```

以 Llama-7B（32 层，4096 维，FP16）为例：

```
2 × 32 × 4096 × 2字节 ≈ 0.5 MB / token
```

- 128K 上下文 → **64 GB**（一张 A100 没了）
- 1M 上下文 → **512 GB**（需要一个服务器集群伺候一个用户）

### 解法组合拳

- **GQA/MQA（分组查询注意力）**：多个 Q 头共享一组 K/V，缓存缩小 8-64 倍（现在几乎所有模型标配）
- **PagedAttention（vLLM，2023）**：像操作系统管理内存页一样管理 KV Cache，消除碎片，吞吐提升数倍
- **KV Cache 量化/压缩/驱逐**：FP8 存储、驱逐不重要的 token（StreamingLLM 发现"注意力水槽"现象，保住开头几个 token 即可）

## 3. 限制三：位置编码的外推失效

这是最隐蔽的一关。模型在 4K 长度上训练，直接给它 100K，**效果不是缓慢下降，而是直接崩溃**——因为位置编码没见过 100K 的位置。

### 位置编码的演化

| 方案 | 年份 | 思想 |
|---|---|---|
| 正弦位置编码 | 2017 | 固定波形，外推性差 |
| 学习式位置嵌入 | 2018 (GPT) | 可学但完全无法外推 |
| **RoPE（旋转位置编码）** | 2021 | 把位置变成向量的**旋转角度**，相对位置 = 角度差；效果好，成为事实标准（Llama/Qwen/DeepSeek 全用它） |
| ALiBi | 2022 | 不给位置编码，直接给远距离的注意力打分**加惩罚偏置**；外推性好 |

### 把 RoPE"拉长"的技术

- **位置插值（PI，2023）**：把 100K 的位置**压缩**映射回训练时见过的 4K 范围，再少量微调
- **NTK-aware / YaRN（2023）**：更精细的"频率分段缩放"——高频（近距离）不动，低频（远距离）压缩，微调成本更低
- **长文本继续预训练**：终究要在真长文本上训一训，模型才能真正适应

> 💡 这就是为什么各家模型版本更新时，上下文窗口常常"原地翻倍"——不是架构变了，而是**位置编码拉伸 + 长文训练**成熟了。

## 4. 限制四：注意力稀释——塞得进 ≠ 用得好

就算工程全解决了，还有一个更本质的问题：**信息越多，注意力越分散**。

- **Lost in the Middle（2023 研究）**：关键信息放在长上下文**中间**时，模型的利用率显著低于放在开头/结尾——注意力天然不均
- 大海捞针测试（在 1M token 里藏一句话）能过，但**多针推理、跨段落综合**的真实任务上，长上下文模型的表现仍明显衰减
- 这解释了为什么 RAG（检索增强）没有死：与其把 1M 全塞给模型，不如精准检索最相关的 10K——**又便宜又准确**（你目录里那本书第 2、3 章把"上下文工程"称作决定 Agent 上限的关键，正是这个逻辑）

## 5. 所以"1M"是什么？

它是当前技术组合（FlashAttention + GQA + RoPE 拉伸 + 长文训练）下，**成本、显存、质量三者的甜点**，不是物理极限：

- Gemini 1.5 Pro（2024.2）率先到 1M；2025 年 GPT-4.1、Claude Sonnet 4（1M beta）、Kimi K2 等跟进
- 再往上（10M+）：计算成本、KV Cache、训练数据稀缺、注意力稀释一起压过来，目前不划算——**等待下一代架构或内存技术**

## 📌 本课要点

1. 1M 限制 = O(n²) 计算 + KV Cache 显存 + 位置外推失效 + 注意力稀释，四者叠加
2. FlashAttention 是 IO 优化而非近似；GQA 砍 KV Cache；RoPE 拉伸管外推
3. 上下文窗口翻倍主要靠工程组合拳，不是架构革命
4. 塞得进 ≠ 用得好：精准上下文工程（RAG/压缩/隔离）长期与长窗口并存
